Core loop & route map

One spine (Path), one detail level (Node), one optional sub-level (Practice — the node's own step). No deeper nesting. Structure and copy only — no colour. Revised 2026-09-03 per ADR-015: challenge belongs to the node; path is a self-contained sectioned sequence (no knowledge-graph link); S6/S7 responsive.

The core loop

S0Landing — one line of context + a way in
S1Sign in — Google auth via Clerk <SignIn />
S2Registering — interstitial while POST /users runs
S3Registration error — recover a failed registration
S4My Path (holding) — path isn't ready yet
S5My Path — steps in order, grouped into competency sections
S6Node / Lesson — video-first + timed resources + the practice step
S7Practice — the node's challenge; immersive, in-shell; result inline
S8Not found — 404

Route map

/ signed out → Landing (S0) signed in → redirect /path /sign-in Sign in (S1) [public] /welcome Registering (S2) [auth] /welcome/error Registration err (S3) [auth] /path My Path (S5) / S4 [requiresAuth] /path/nodes/:nodeId Node / Lesson (S6) [requiresAuth] /path/nodes/:nodeId/practice Practice (S7) [requiresAuth] /:pathMatch(.*)* Not found (S8)
Named routes only — home, sign-in, registering, registration-error, path, node, practice, not-found. Components never hardcode paths. requiresAuth waits for both the Clerk session and registration to resolve; an unregistered signed-in user is routed to /welcome.

Shared state components

StateLoading StateEmpty StateError StateLocked
In src/shared/components/. Every screen that fetches data uses them. data-test hooks stay stable: loading · no-path · error · retry · locked. The holding state (S4) is StateEmpty with fixed copy.

Chrome

Header on all authenticated screens: logo + wordmark · one nav link "My path" · "Sign out" pushed right. Context bar on S6 / S7 only ("‹ Back to path" / "‹ Back to lesson") — browser back does the same thing. No footer, breadcrumbs, or sidebar in the alpha.
